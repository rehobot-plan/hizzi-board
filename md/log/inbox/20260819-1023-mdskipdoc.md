# mdskipdoc — 빌드 스킵 사실을 앱 문서에 (작업 레인 조각)

## 1. 탐색·검색

내부 — `vercel.json` 원본을 먼저 읽었다. 지시서가 적은 요약을 근거로 안 썼다. 이어서 `md/core/master.md` 10장(CLI·미리보기·고객 배포·1-5)과 `md/log/todo.md` 미해결을 열었다.

외부 — Vercel 원문 셋을 열었다(R-EXT). 종료값 뜻과 기준점 정의를 기억으로 안 적었다.

- 종료값 — "If the command exits with code `1`, the build continues as normal" · "If the command exits with code `0`, the build is immediately aborted, and the deployment state is set to `CANCELED`". 같은 뜻이 `vercel.json` 문서에도 한 번 더 적힌다("When the command exits with code 1, the build will continue. When the command exits with 0, the build is ignored.").
- 셈 — "Canceled builds are counted as full deployments as they execute a build command in the build step."
- 기준점 — `VERCEL_GIT_PREVIOUS_SHA` 는 "The git SHA of the last successful deployment for the project and branch" 이고 "only exposed when an Ignored Build Step is provided" 다.

**지시서가 안 적은 것 하나를 원문이 더 줬다** — 그 값은 **프로젝트와 가지별**이다. 다른 가지의 성공 배포는 기준이 안 된다. 문서에 그 줄을 함께 넣었다.

## 2. 구현

파일 하나. `md/core/master.md`.

**절 하나를 세웠다** — `### MD 만 바뀐 push 는 빌드가 안 선다 (2026-08-19)`. 자리는 고객 배포 절 뒤, 1-5 절 앞이다. 그 앞 절이 승인 자리를 지고 이 절이 그 자리를 기계가 어떻게 돕는지를 적으므로 이어 읽힌다.

담은 것 —

- 무엇이 그러나 — 담기는 무늬 둘(`md/` 아래 `.md` · 뿌리에 바로 놓인 `.md`)과 **그 둘 밖은 안 담긴다**는 것. `docs/x.md` 같은 자리를 예로 들었다. **판정 자체는 `vercel.json` 이 정본이라 그 문자열을 문서로 옮겨 적지 않았다.**
- 화면에 무엇이 뜨나 — 배포가 안 뜨는 것이 아니라 `Canceled` 로 뜬다. 취소된 빌드도 배포 셈에 들어간다.
- 왜 세웠나 — MD 만 바뀐 push 가 고객 배포를 만들던 자리를 막는다(오너 결정 2026-08-19).
- 잣대 — 가르는 물음을 두 줄로 세웠다. 아닌 것은 "이 커밋이 MD 만인가", 맞는 것은 "마지막 성공 배포 이후 누적이 전부 MD 인가". 부모 커밋이 아니라는 것과 가지별이라는 것을 원문 인용과 함께 적었다. 손으로 재는 줄도 하나 넣었다.
- 고장이 아니다 — 첫 줄에 세웠다. "push 했는데 새 배포가 안 뜨거나 `Canceled` 로 뜨는 것이 정상일 수 있다."
- 닫는 것과 안 닫는 것 — 원장만 올리는 push 는 닫히고 **통합 push 는 안 닫힌다.** 이어서 "이 스킵이 있으니 승인이 필요 없다고 읽지 않는다"를 적었다.
- 안 나가는 갈래와 못 나가는 갈래 — 상태로 가르게 했다. 이 스킵은 `CANCELED`, 별건은 `failure` 에 로그가 `auth/invalid-api-key` 다.
- 빌드를 세우는 쪽으로 떨어지는 갈래 넷을 적었다. 원본이 그 넷에서 전부 종료값 1 로 빠져나간다.

**낡은 줄 하나를 함께 고쳤다.** 미리보기 절이 *"Git 연동이 살아 있고 `vercel.json` 이 없어 막는 줄도 없다"* 로 적고 있었는데 오늘 그 파일이 섰다. 그 문장을 갈라 새 절을 가리키게 했다. **지시서가 지목한 자리는 아니지만 같은 문서 안에서 새 절과 정면으로 어긋나는 문장이라 그대로 두면 읽는 사람이 둘 중 하나를 믿는다.**

## 3. 빌드 검증

게이트 셋을 하나씩 단독으로 불렀다. 전부 종료값 0.

- `npm run lint` — 0. 경고는 이 회차와 무관한 기존 것이다.
- `npm run build` — 0.
- `npm run test:unit` — 0. 검사 파일 6 · 검사 48 통과 · 1.15초.

**한 번 파이프에 물렸다.** 빌드를 `| tail -18` 로 불러 종료값이 **빈 값**으로 왔다. 그 문서 10장이 정확히 그 자리를 금하고 있고(*"파이프에 물리면 종료값이 뒤엣것 것으로 바뀌어 붉음이 조용히 삼켜진다"*) 지시서도 단독으로 부르라 했는데 밟았다. 단독으로 다시 불러 0 을 읽었다.

**불필요한 호출 하나도 냈다.** `scripts/stamp-version.js` 를 층 다리로 돌려 `public/version.txt` 를 새로 찍었다(`dev-1787102534690`). 그 파일은 무시 대상이라 커밋에 안 들어가고 빌드가 어차피 다시 찍는다. 회차에 필요 없던 걸음이라 적어 둔다.

## 6. 배포

**비해당 — MD 전용** (그 문서 고객 배포 절 · 오너 결정 2026-08-19). 이 회차가 문서로 적은 그 규칙이 이 회차 자신에게 먼저 걸린다.

가지 커밋과 push 는 했다. **그 push 로 미리보기 빌드가 서지 않는 것이 정상이다** — 이 회차의 변경이 `md/core/master.md` 하나이고 누적도 그것뿐이라 스킵 조건에 그대로 맞는다. 서면 오히려 잣대를 다시 봐야 한다.
